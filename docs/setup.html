1 Архитектура подключения

Один источник правды для всех файлов сайта.

WebMu использует единый front-controller index.php, который подключает core/init.php. Bootstrap загружает opt.php в массив $config и передаёт его в core/db.php. Все модули (modules/*.php), виджеты (modules/widgets/*.php), языковые файлы и шаблоны читают параметры подключения только из $config — никогда не хардкодят логин/пароль/имя БД.

┌─────────────┐
│   opt.php   │  ← вы редактируете только этот файл
└──────┬──────┘
       │ require
┌──────▼──────────┐
│  core/init.php  │  ← наполняет $config, стартует сессию
└──────┬──────────┘
       │ require core/db.php
┌──────▼──────────┐    ┌─────────────────┐
│ db_build_dsn()  │ →  │  odbc_connect() │ → MS SQL Server
│ db()            │    └─────────────────┘
└──────┬──────────┘
       │ db_query / db_one / db_all / db_exec
┌──────▼──────────┐
│ modules/*.php   │  account · ranking · register · vote · donate · ...
└─────────────────┘
Ключевой принцип: чтобы переехать на другой сервер БД — достаточно поменять значения в opt.php. Код модулей трогать не нужно.

2 Требования к серверу prerequisites

Веб-сервер

PHP 7.4+ или 8.x

Расширение php_odbc включено в php.ini

Apache / Nginx / IIS — любой

База данных

Microsoft SQL Server 2008 R2+

Включён TCP/IP в SQL Server Configuration Manager

Открыт порт 1433 (или иной)

База MuOnline

Развёрнутая БД MuOnline (Season 3 Episode 1)

Доступ к таблицам MEMB_INFO, Character, Guild, MEMB_STAT и др.

Сетевая связность

С веб-сервера до SQL Server открыт TCP-порт

Проверка: telnet 192.168.0.10 1433

3 Подготовка SQL Server

Создайте отдельный логин для сайта — никогда не используйте sa.

Подключитесь к SQL Server через SSMS под sa и выполните:

-- 1. Создаём логин уровня сервера
CREATE LOGIN web_app WITH PASSWORD = 'Strong#Pass2026!',
    CHECK_POLICY = ON;

-- 2. Привязываем логин к базе MuOnline
USE MuOnline;
CREATE USER web_app FOR LOGIN web_app;

-- 3. Минимально необходимые права
GRANT SELECT, INSERT, UPDATE ON SCHEMA::dbo TO web_app;

-- 4. Проверяем
SELECT name, type_desc FROM sys.database_principals WHERE name = 'web_app';
Включите Mixed Mode Authentication в свойствах SQL Server, иначе SQL-логин работать не будет. После изменения перезапустите службу SQL Server.

Откройте SQL Server Configuration Manager → SQL Server Network Configuration → Protocols for MSSQLSERVER и убедитесь, что TCP/IP = Enabled, а во вкладке IP Addresses в разделе IPAll указан порт 1433.

4 Установка ODBC-драйвера

PHP подключается к MS SQL через ODBC.

Windows

В большинстве серверных Windows-сборок драйвер SQL Server уже доступен. Для современных версий рекомендуется Microsoft ODBC Driver 17/18 for SQL Server:

https://learn.microsoft.com/sql/connect/odbc/download-odbc-driver-for-sql-server

После установки укажите его в opt.php:

$config["odbc_driver"] = "ODBC Driver 17 for SQL Server";

Linux

# Debian / Ubuntu
sudo apt-get install unixodbc unixodbc-dev php-odbc
# затем установите msodbcsql17 по инструкции Microsoft

Проверьте, что драйвер виден:

odbcinst -q -d

PHP

php -m | grep -i odbc      # должно вывести: odbc
Если в логе видите «ODBC extension is not installed — database features disabled.» — значит расширение PHP-ODBC не загружено. Раскомментируйте extension=odbc в php.ini и перезапустите веб-сервер.

5 Создание opt.php

Это единственный файл с реальными секретами. Он добавлен в .gitignore.

# из корня сайта
cp opt.example.php opt.php
chmod 640 opt.php          # читать может только владелец и группа веб-сервера

Откройте opt.php в любом редакторе и заполните параметры. Структура файла:

  • Блок Database — хост, порт, логин, пароль, имя БД, ODBC-драйвер.
  • Блок Optional remote-connection tuning — таймаут, charset, persistent, готовый DSN.
  • Блок Site addresses — адрес сайта и форума.
  • Блоки Currency mapping, Char/Guild/Stat tables — маппинг таблиц MuOnline.
  • Блок Vote sites, Downloads — внешние ссылки и тексты.
Никогда не коммитьте opt.php в Git. Если пароль попал в историю — немедленно смените его в SQL Server.

6 Базовые ключи подключения

Минимальный набор, который обязан быть заполнен реальными значениями:

КлючНазначениеПример
db_hostIP или DNS-имя SQL Server192.168.0.10
db_portTCP-порт (если не 1433)1433
db_userSQL-логин (не sa)web_app
db_upwdПароль логинаStrong#Pass2026!
db_nameИмя базы данныхMuOnline
odbc_driverИмя установленного ODBC-драйвераODBC Driver 17 for SQL Server

Пример заполненного блока:

$config["db_host"]     = "192.168.0.10";
$config["db_port"]     = "1433";
$config["db_user"]     = "web_app";
$config["db_upwd"]     = "Strong#Pass2026!";
$config["db_name"]     = "MuOnline";
$config["odbc_driver"] = "ODBC Driver 17 for SQL Server";
При старте сайта db_validate_config() проверит, что все обязательные ключи заполнены и пароль не равен значению-заглушке CHANGE_ME. Если что-то не так — вы увидите понятное сообщение, а не таинственный белый экран.

7 Расширенные ключи: порт, таймаут, DSN

Опциональные настройки для тонкого тюнинга подключения.

КлючПо умолчаниюОписание
db_dsn(пусто)Полная DSN-строка. Если задана — игнорирует db_host/port/name/odbc_driver.
db_appnameWebMuИмя приложения, которое видно в sp_who2 на стороне SQL Server.
db_charset(драйвер)Например UTF-8 при использовании MSODBCSQL.
db_timeout5Таймаут логина в секундах (0 = по умолчанию драйвера).
db_persistent01 — пул соединений через odbc_pconnect.

Когда использовать db_dsn

Полезно для нестандартных сценариев: TLS-соединение, именованный экземпляр, доверие к самоподписанному сертификату:

$config["db_dsn"] = "Driver={ODBC Driver 18 for SQL Server};"
                  . "Server=tcp:db.example.com,1433;"
                  . "Database=MuOnline;"
                  . "Encrypt=yes;TrustServerCertificate=yes;";

Альтернатива записи порта

SQL Server-овский синтаксис «host,port» по-прежнему работает — просто оставьте db_port пустым:

$config["db_host"] = "192.168.0.10,1433";
$config["db_port"] = "";

8 Маппинг таблиц MuOnline

Структура схемы у разных репаков отличается. Названия таблиц/колонок берутся из opt.php, а не из кода.

Все запросы к таблицам персонажей, гильдий, статистики и валют используют значения из $config и проходят через хелпер db_ident(), который безопасно квотит идентификатор. Поэтому смена схемы — это правка opt.php, не модулей.

ГруппаКлючи в opt.php
Персонажиchar_table, char_name_col, char_account_col, char_level_col, char_resets_col, char_master_col, char_class_col, char_pk_count_col, char_pk_level_col
Гильдииguild_table, guild_member_table, guild_name_col, guild_master_col, guild_score_col
Онлайн-статистикаstat_table, stat_account_col, stat_connect_col
Валютыcr_*, usd_*, wcoin_*, gr_* (table / column / acc)
Donate / Votedonate_items_table, donate_log_table, vote_sites

Опциональные WebMu-таблицы (например WebDonateLog) проверяются через db_table_exists(): если таблицы нет — соответствующий блок просто скрывается, ошибки не возникнет.

9 Проверка подключения

Три способа убедиться, что сайт видит базу.

А. Открыть главную страницу

Если в шапке появляется красный баннер «Нет подключения к удалённой базе данных» — детали смотрите в logs/db.log.

Б. Через CLI-скрипт

php -r 'define("insite",1);
require "core/init.php";
var_dump(db_ping());
echo db_last_error(), PHP_EOL;'

db_ping() установит соединение и выполнит SELECT 1. Возвращает true, если БД доступна с текущими настройками opt.php.

В. Через лог

Если в opt.php установить $config["debug"] = 1;, ошибки SQL/ODBC будут выводиться прямо в браузер. На продакшене обязательно верните 0.

tail -f logs/db.log

10 Использование $config в модулях

Так устроены ВСЕ модули — следуйте тому же шаблону при доработках.

Никаких odbc_connect() в модулях. Никаких хардкодов имён таблиц. Только функции из core/db.php и значения из $config.

// modules/account.php — чтение баланса
global $config;
$tbl = db_ident($config["cr_table"]);     // [MEMB_INFO]
$col = db_ident($config["cr_column"]);    // [credits]
$acc = db_ident($config["cr_acc"]);       // [memb___id]

$row = db_one(
    "SELECT $col AS balance FROM $tbl WHERE $acc = ?",
    [$_SESSION["uid"]]
);
  • db_query($sql, $args) — параметризованный запрос (?-плейсхолдеры).
  • db_one($sql, $args) — одна строка (или null).
  • db_all($sql, $args) — массив строк.
  • db_exec($sql, $args) — INSERT/UPDATE/DELETE.
  • db_ident($name, $fallback) — безопасное квотирование идентификатора из $config.
  • db_table_exists($name) — проверка опциональных таблиц.
  • Никогда не склеивайте пользовательский ввод в строку SQL — только через ?.
  • Никогда не пишите "MEMB_INFO.credits" в коде — читайте $config["cr_table"] / cr_column.

11 Решение типичных проблем

Сообщение / симптомПричина и решение
opt.php is missing or has placeholder values for: db_upwd (still set to CHANGE_ME)Вы скопировали шаблон, но не заменили пароль. Откройте opt.php и впишите реальный.
ODBC extension is not installedВключите extension=odbc в php.ini и перезапустите веб-сервер.
SQLSTATE[08001] / Login timeout expiredВеб-сервер не достучится до SQL Server. Проверьте firewall, TCP/IP в SQL Server Configuration Manager, порт 1433.
SQLSTATE[28000] Login failed for user 'web_app'Неверный логин/пароль или не включён Mixed Mode Authentication в свойствах сервера.
Cannot open database "MuOnline" requested by the loginЛогину не выдан доступ к базе. Выполните CREATE USER ... FOR LOGIN ... и GRANT.
Loaded opt.example.php — copy it to opt.phpФайла opt.php ещё нет. Скопируйте шаблон: cp opt.example.php opt.php.
Invalid SQL identifier `...`В opt.php в одном из char_*/guild_*/cr_* ключей задано имя с пробелами/спецсимволами. Допустимы только [A-Za-z0-9_].
Все ODBC-ошибки дублируются в logs/db.log с временной меткой. При debug=1 — ещё и в HTML страницы (только для разработки!).

12 Чек-лист безопасности

  • opt.php в .gitignore, секреты не уезжают в репозиторий.
  • Используется выделенный SQL-логин с минимальными правами (SELECT/INSERT/UPDATE), не sa.
  • Пароль изменён со значения-заглушки CHANGE_ME.
  • Все запросы идут через db_query() с параметризацией — нет ручной конкатенации.
  • В продакшене $config["debug"] = 0; — ошибки только в лог.
  • Файл opt.php доступен веб-серверу на чтение, но не миру (chmod 640).
  • Логи logs/ и кеш cache/ не доступны напрямую через HTTP (используйте правила веб-сервера).
  • SQL Server слушает не на публичном интерфейсе или защищён файрволом по IP.
Готово! Сайт WebMu подключён к удалённой базе данных. Все будущие изменения параметров подключения делаются только в файле opt.php.
